## 1. Overview & Verification Standard

This document provides the mathematical cardinalities, temporal sequencing constraints, referential integrity rules, and financial consistency formulas required to generate interconnected, valid synthetic insurance datasets across Guidewire PolicyCenter and ClaimCenter.

> [!IMPORTANT]
> Every cardinality and validation constraint in this document is verified against the installed Guidewire data model definitions (`.eti`), database constraints (`<checkconstraint>`), check builders (`dbchecks`), or Gosu domain logic. Any property that cannot be confirmed from the local source files is explicitly marked as `"Not verified in source."`

## 2. PolicyCenter Entity Cardinalities (Verified from Source)

### Account to Subordinate Entities
- **1 Account -> 1 AccountHolderContact** (`Account.AccountHolderContact`, `nullok="false"` in `Account.eti`). Exactly one primary contact entity represents the account owner.
- **1 Account -> 1 PrimaryLocation** (`Account.PrimaryLocation`, `nullok="false"` in `Account.eti`). Every account must possess a default primary location.
- **1 Account -> 1..N AccountLocation** (`Account.AccountLocations` array, `arrayentity="AccountLocation"` in `Account.eti`). Minimum 1 location (the primary location), with additional secondary locations as needed.
- **1 Account -> 1..N AccountContact** (`Account.AccountContacts` array in `Account.eti`). An account maintains an array of associated contacts (drivers, owners, billing contacts).
- **1 Account -> 1 ProducerCodeOfService** (`Account.ProducerCodeOfService`, `nullok="false"` in `Account.eti`). Managing agency/producer code.
- **1 Account -> 0..N Policies** (`Account.Policies` array in `Account.eti`). A new account begins with 0 policies until a submission is bound.

### Policy & PolicyPeriod Cardinalities
- **1 Policy -> 1..N PolicyPeriod** (`Policy.Periods` array in `Policy.eti`). A policy spans multiple periods over its lifecycle (e.g. Term 1, Renewal Term 2, PolicyChange slice).
- **1 Policy -> 1..N Jobs** (`Policy.Jobs` array in `Policy.eti`). Every policy action (Submission, Renewal, PolicyChange, Cancellation, Reinstatement) creates a job.
- **1 PolicyPeriod -> 1 Job** (`PolicyPeriod.Job`, `nullok="false"` in `PolicyPeriod.eti`). Every period is owned by an originating or modifying job.
- **1 PolicyPeriod -> 1 PolicyTerm** (`PolicyPeriod.PolicyTerm`, `nullok="false"` in `PolicyPeriod.eti`). Represents the fiscal/annual boundary of coverage.
- **1 PolicyPeriod -> 1..N PolicyLine** (`PolicyPeriod.Lines` array in `PolicyPeriod.eti`). Monoline policies contain exactly 1 line (e.g. `PersonalAutoLine`); package policies (`CommercialPackage`) contain 1..N lines (`CPLine`, `GLLine`, `IMLine`).
- **1 PolicyPeriod -> 1..N PolicyContactRole** (`PolicyPeriod.PolicyContactRoles` array in `PolicyPeriod.eti`). Every period requires at least 1 `PolicyPriNamedInsured`.
- **1 PolicyPeriod -> 0..N PolicyLocation** (`PolicyPeriod.PolicyLocations` array in `PolicyPeriod.eti`).
- **1 PolicyPeriod -> 0..N Costs** (`PolicyPeriod.Costs` array in `PolicyPeriod.eti`). Generated by rating engine during quoting.
- **1 Cost -> 0..N Transactions** (`Cost.Transactions` array in `Cost.eti`). Financial ledger entries for billing.

### PolicyLine to Coverables & Coverages
- **PersonalAutoLine:**
  - `1 PersonalAutoLine -> 1..N PersonalVehicle` (`PersonalAutoLine.Vehicles` array). An auto policy must cover at least 1 vehicle.
  - `1 PersonalAutoLine -> 1..N VehicleDriver` (`PersonalAutoLine.Drivers` array). At least 1 driver must be registered.
  - `1 PersonalVehicle -> 0..N PersonalVehicleCov` (`PersonalVehicle.Coverages` array). Vehicle-level coverages (Collision, Comprehensive, Towing).
  - `1 PersonalAutoLine -> 0..N PersonalAutoCov` (`PersonalAutoLine.PACoverages` array). Line-level coverages (Liability, Uninsured Motorist, MedPay).
- **CommercialPropertyLine:**
  - `1 CPLine -> 1..N CPLocation` (`CPLine.CPLocations` array).
  - `1 CPLocation -> 1..N CPBuilding` (`CPLocation.Buildings` array).
  - `1 CPBuilding -> 1..N CPBuildingCov` (`CPBuilding.Coverages` array).
- **BusinessOwnersLine:**
  - `1 BOPLine -> 1..N BOPLocation -> 1..N BOPBuilding -> 1..N BOPBuildingCov`.
- **HOPLine (Homeowners):**
  - `1 HOPLine -> 1 HOPDwelling -> 1..N HOPDwellingCov`.
- **Coverage -> CovTerms:**
  - `1 Coverage -> 1..N CovTerms` (Defined in Product Model XML: Limits, Deductibles).

## 3. ClaimCenter Entity Cardinalities (Verified from Source)

### Claim to Subordinate Objects
- **1 Policy -> 0..N Claims** (A policy in-force may experience 0 or multiple independent claims).
- **1 Claim -> 1 Policy** (`Claim.Policy`, `nullok="false"` in `Claim.eti`). In Guidewire, every claim is linked to exactly one policy (either verified in PolicyCenter or an unverified policyholder snapshot).
- **1 Claim -> 1..N ClaimContact** (`Claim.Contacts` array in `Claim.eti`). At minimum: Insured, Reporter, MainContact.
- **1 Claim -> 1..N Incident** (`Claim.Incidents` array in `Claim.eti`). Represents physical damage or injury events resulting from the loss.
- **1 Claim -> 0..N Exposures** (`Claim.Exposures` array in `Claim.eti`). An open incident-only report has 0 exposures. A processed claim requires 1..N exposures.
- **1 Exposure -> 1 Incident** (`Exposure.Incident`, `nullok="true"` in database schema, but business rules enforce association).
- **1 Exposure -> 1 Coverage** (`Exposure.PrimaryCoverage`, `nullok="true"` in schema for non-covered losses; business logic links to verified policy coverage).
- **1 Exposure -> 1 Claimant** (`Exposure.Claimant`, `nullok="false"` in `Exposure.eti`).
- **1 Claim -> 0..N TransactionSets** (`Claim.TransactionSets` array in `Claim.eti`).
- **1 CheckSet -> 1..N Checks** (`CheckSet.Checks` array in `CheckSet.eti`). Typically 1 check per check set.
- **1 Check -> 1..N Payments** (`Check.Payments` array in `Check.eti`). A check can bundle multiple payments across different exposures or cost categories.
- **1 ReserveLine -> 0..N Reserves** (`ReserveLine.eti`). Tracks cumulative reserve adjustments.
- **1 ReserveLine -> 0..N Payments** (`ReserveLine.eti`). Tracks cumulative disbursements.
- **1 Claim -> 0..N Matters** (`Claim.Matters` array in `Claim.eti`). Legal actions / litigation.
- **1 Claim -> 0..N ServiceRequests** (`Claim.ServiceRequests` array in `Claim.eti`). Vendor service dispatches.

## 4. Temporal Sequencing Rules

Synthetic data generation algorithms MUST observe the following chronologically strict rules:

### Policy Center Chronology
1. **Account Origination:** `Account.OriginationDate <= Policy.OriginalEffectiveDate`.
2. **Policy Period Boundaries:** `PolicyPeriod.PeriodStart < PolicyPeriod.PeriodEnd`.
3. **Standard Terms:**
   - Annual: `PeriodEnd = PeriodStart + 1 year`.
   - Six Months: `PeriodEnd = PeriodStart + 6 months` (Standard personal auto).
4. **Job Sequences:**
   - Submission Job: Initiates Term 1.
   - Policy Change Job: `ChangeEffectiveDate` must satisfy `PeriodStart <= ChangeEffectiveDate < PeriodEnd`.
   - Cancellation Job: `CancellationDate` must satisfy `PeriodStart <= CancellationDate <= PeriodEnd`.
   - Reinstatement Job: `ReinstatementDate == CancellationDate`.
   - Renewal Job: `NewPeriod.PeriodStart == PriorPeriod.PeriodEnd`.

### Claim Center Chronology
1. **Loss Date Validity:** `PolicyPeriod.PeriodStart <= Claim.LossDate <= PolicyPeriod.PeriodEnd`. (A claim cannot occur outside active coverage).
2. **Reporting Latency:** `Claim.LossDate <= Claim.ReportedDate`. Typically `ReportedDate` occurs between 0 hours and 14 days after loss.
3. **Claim Assignment:** `Claim.ReportedDate <= Claim.AssignmentDate`.
4. **Exposure Creation:** `Claim.ReportedDate <= Exposure.CreateTime`.
5. **Initial Reserve Timing:** `Exposure.CreateTime <= InitialReserve.CreateTime`. Underwriting guidelines typically mandate reserves within 24 to 72 hours of exposure creation.
6. **Payment Disbursement:** `InitialReserve.CreateTime <= Payment.CreateTime`. Payments cannot precede reserve creation.
7. **Check Clearing:** `Check.IssueDate <= Check.DateCleared` (if status = `cleared`).
8. **Claim Closure:** `Claim.CloseDate >= MAX(All Payments CreateTime)`. All financial transactions must settle before closure.

## 5. Financial & Mathematical Integrity Rules

### Check Amount Consistency
```
Check.GrossAmount == SUM(Payment.Amount) for all Payments linked to Check
Check.NetAmount == Check.GrossAmount - Check.Deductions
```

### Exposure Reserve Balance Equation
For each unique `ReserveLine` (Claim + Exposure + CostType + CostCategory):
```
OpenReserves == TotalReservesIncurred - TotalPaymentsMade
Constraint: OpenReserves >= 0  (Unless negative reserve transactions are authorized for recovery)
TotalIncurred == TotalReservesIncurred
```

### Deductible & Coverage Limit Constraints
1. `Payment.Amount <= Coverage.IncidentLimit` (per loss).
2. `Payment.Amount <= Coverage.ExposureLimit` (per claimant/exposure).
3. If deductible applies: `NetPaid = LossAmount - Deductible.Amount`.
